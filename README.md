# NIChecker: Bounded Verification of Atomicity Violations for Interrupt-Driven Programs

This repository provides the experimental benchmarks, raw data, and results associated with the research paper published in **ACM Transactions on Software Engineering and Methodology (TOSEM)**.

## Project Overview
NIChecker is a bounded verification tool specifically designed for detecting atomicity violations in interrupt-driven programs using a lazy sequentialization approach. It addresses the challenges of interrupt context switching and non-deterministic execution to ensure the reliability of embedded software.

## Repository Structure
- `NIChecker_Experiments/`: Contains the primary benchmarks and the verification results generated by NIChecker.
- `Comparison_CPA4AV_Experiments/`: Contains experimental data and results for **CPA4AV** (from ESEC/FSE'23) using our benchmarks.
- `Comparison_iCBMC_Experiments/`: Contains experimental data and results for **iCBMC** (from TECS'17) using our benchmarks.
- `LICENSE`: Apache-2.0 license for the shared benchmarks and experimental data.

## Data Reproducibility
To ensure the transparency and validity of the results presented in our paper, this repository includes:
- **Benchmarks**: Source code for the interrupt-driven programs used in the evaluation.
- **Experimental Results**: Detailed logs, verification times, and detection results for NIChecker and state-of-the-art comparison tools.

## Source Code Availability & Access Protocol

### Why the Source Code is Private
The full source code of the NIChecker tool is currently **not publicly available** due to the following reasons:
1. **Intellectual Property:** The tool is part of a collaborative project and is currently protected by **pending patents**.
2. **Ongoing Development:** The tool is undergoing further iteration and optimization for industrial application scenarios.

### Formal Request Protocol
We are committed to supporting academic research and are open to sharing the NIChecker tool (source code or executable) for **legitimate research purposes and comparative studies**. 

To maintain academic integrity and professional communication, we will **not** respond to anonymous requests or inquiries with insufficient background information. If you wish to request access to the tool, please send a **formal email** to the corresponding author. Your request **must** include:

1. **Full Name** and professional title.
2. **Institutional Affiliation** (e.g., University, Research Laboratory, or Department).
3. **Institutional Email Address:** Please use your official email (e.g., `@university.edu`) for the request.
4. **Detailed Purpose:** A clear description of your intended use for the tool (e.g., for comparison in an upcoming study on [Topic]).

*Note: The authors reserve the right to evaluate and decline requests that do not comply with these professional standards.*
